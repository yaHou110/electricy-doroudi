# Contributing

## Commit conventions

- Write conventional, descriptive commit messages focused on the change and its intent.
- Do not include AI-tool names, co-author trailers referencing tools, or generation metadata in commits, documentation, issues, or pull requests.
- Keep each commit logically scoped to one change.
- Run the verification suite before pushing: typecheck, lint, tests, and build.

## Documentation

- Product and business documentation lives in `docs/`.
- Architectural decisions are recorded in `docs/ARCHITECTURE.md`.
- Scope boundaries are defined in `docs/ROADMAP.md` and enforced in review.
